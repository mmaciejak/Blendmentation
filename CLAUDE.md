# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Blendmentation is a Python library for generating synthetic, augmented training datasets (renders, passes, AOVs, segmentation masks and labels) from Blender scenes. It is modelled after torchvision/albumentations-style transforms: you compose augmentations, apply them to Blender objects, render, then restore the scene and repeat.

**Approach** (the README and docs home page say it too): the variation in a pipeline lives in the user's Blender scene, in shader and geometry nodes, and Blendmentation changes their values (`Number`, `Vector`, `Boolean`, `Menu`, `Node`, `Seed`). Prefer that over new special-purpose augmentations; the exceptions are shortcuts for common basic setups (`KeepAbove`, `PlaceOn`, `LookAt`, `SimpleMaterial`, `FocalLength`, `DepthOfField`), and the transforms, for simple scenes and small changes outside geometry nodes (cluttered scenes: geometry nodes). The generating step is not part of usual Blender workflows apart from the color render, so it does its work itself.

## Running

Packaging is in `pyproject.toml`; there is no linter config. The code depends on `bpy`, `mathutils`, `numpy` and `OpenImageIO` and is meant to run inside Blender's bundled Python (e.g. Blender's scripting tab, or `blender --background scene.blend --python example.py`). `example.py` shows the intended usage of every feature; its docstring lists the scene it expects. It adds its own folder to `sys.path`. Import the modules as a package (`from blendmentation.augmentations import augmentations`), because they import their `bpy_*` sibling relatively.

**Tests** are in `tests/` (pytest) and run with `bpy` as a Python module:
```sh
uv venv --python 3.13 .venv && VIRTUAL_ENV=.venv uv pip install -e ".[module,test,dev]"   # bpy 5.x
uv venv --python 3.11 .venv311 && VIRTUAL_ENV=.venv311 uv pip install "bpy==4.5.14" -e ".[module,test]"  # bpy 4.x
.venv/bin/python -m pytest                      # all
.venv/bin/python -m pytest tests/test_generating.py::test_keypoints   # one test
```
Run the suite on both. GitHub Actions (`.github/workflows/tests.yml`, on pushes to `main`/`dev` and PRs) runs it on Linux with Mesa's software EGL (Workbench works without a GPU) for bpy 5.x/3.13 and 4.5.14/3.11, plus a no-`bpy` job on 3.10 and 3.12. `release.yml` builds and creates a GitHub release with the wheel and sdist when a `v<version>` tag matching `pyproject.toml` is pushed; the release notes are that version's section of `CHANGELOG.md` (extracted by `.github/scripts/release_notes.py`), and the release fails without one. It does not publish to PyPI yet (the user decided against it for now). The install docs tell users to clone or `pip install git+https://github.com/mmaciejak/Blendmentation`, which is only right because `main` always holds the latest release. **Work on the `dev` branch**; `main` only moves on a release (bump the version on `dev` and turn `## [Unreleased]` in `CHANGELOG.md` into `## [<version>] - <date>` with a new empty `[Unreleased]` above it and updated compare links, fast-forward `main` to it, tag `v<version>`). The docs site deploys from `main`, so it shows the released version. The `dev` extra is `fake-bpy-module` (stub-only `bpy-stubs`, safe next to the real `bpy`), so Pylance/Pyright know the `bpy` types; check typing with `npx pyright --pythonpath .venv/bin/python <files>`. `conftest.py` resets to an empty factory scene (Workbench, Cycles at 1 CPU sample) with a camera at (0, -10, 0) looking along +Y before every test. The `cube` fixture's default size is 1 (half-extent 0.5), and `renders` records the engine of every render started. Without `bpy`, the conftest still loads and only the pure tests (export) run. Workbench and EEVEE need a GPU.

There are no `bpy` wheels for 4.0/4.1, so 4.0 is only checked in the app. On this machine `Blender 4.app` is Blender 5.2 and `Blender.app` is 4.0, e.g. `"/Applications/Blender.app/Contents/MacOS/Blender" -b --factory-startup --python-exit-code 1 --python script.py`.

The code also runs with `bpy` as a plain Python module (`pip install bpy OpenImageIO`; `bpy` 5.1+ needs Python 3.13, 4.x–5.0 need 3.11). Two things keep that working:
- `blendmentation/__init__.py` imports `bpy` first (if it's installed), because `mathutils` is only importable after `bpy` in module mode. Without `bpy`, the `augmentations`, `generating` and `state` subpackages call `require_bpy()` in their `__init__`, which raises an `ImportError` explaining how to get Blender; `export` works.
- Packaging: `numpy` is the only hard dependency. Blender bundles it with pip metadata, so installing into Blender's Python downloads nothing. `bpy` and OpenImageIO are bundled too but invisible to pip, so they are in the `module` extra; a hard dependency would install a second copy into Blender. Installing into Blender with `pip --target` (the user `scripts/modules` folder) needs `--no-deps`, or it installs a numpy that shadows Blender's.
- The `bpy` wheel ships numpy but not OpenImageIO, so `bpy_generating.py` raises an `ImportError` with install instructions when it's missing.

## Architecture

Each subpackage under `blendmentation/` is split into two layers:

- **Public API module** (`augmentations.py`, `generating.py`, `state.py`): user-facing classes that only hold configuration and delegate the actual work.
- **`bpy_*` module** (`bpy_augmentations.py`, `bpy_generating.py`): plain functions that do the real Blender (`bpy`) manipulation. The public classes call these via a module alias (`bpy_a`, `bpy_g`). `state.py` uses the shared `blendmentation/bpy_undo.py`.

Keep this split: Blender-specific logic goes in the `bpy_*` modules, and the public classes stay thin. `blendmentation/bpy_paths.py` is shared by augmentations and generating. It parses data paths like `bpy.data.materials["Mat"].node_tree.nodes["X"].inputs[2].default_value` into attribute/item steps without `eval`, then gets or sets the value and calls `update_tag()` on the owning datablock. Paths starting with `bpy.` are absolute; any other path is relative to an object.

The subpackages:

- **augmentations**: `Compose` applies a list of transforms to each object in a list. Every transform is a callable taking a single `bpy` object, and it **mutates in place**.
  - The public classes are type-hinted with the aliases at the top of `augmentations.py` (`Offset`, `RangeOrValue`, `Target`, `Bound`); `bpy.types.Object` is imported under `TYPE_CHECKING` only, with `from __future__ import annotations`, so nothing extra is imported at runtime.
  - Every transform subclasses `Augmentation`, takes `p` (probability it runs, default 1, drawn per call, so per object in a `Compose`) and implements `apply(obj)`; `__call__` draws `p`, sets `applied`, and on a skip calls `skip()`, which sets `actual` (or `actual_x/y/z`) to `None`, or, when `otherwise` is not None, calls `set_otherwise(obj)` and stores what it set. `Number`, `Vector`, `Boolean`, `Menu`, `Visibility`, `FocalLength` (not with `keep_size`) and `DepthOfField` (`False` only: DoF off, `disable_depth_of_field`) take `otherwise`, validated in `__init__` (`check_otherwise`); the data-path ones set it by calling their sampler with `(v, v)`. A `Compose` skipped by its own `p` doesn't set `otherwise`. `p=1` draws no random number. `Compose` also takes `p`, drawn once per call. A call can override `p`, for a `Compose` (`compose(objects, p=0.5)`) and for any augmentation (`aug(obj, p=0.5)`, `aug(p=0.5)`). `Boolean` and `Visibility` default to `otherwise=False`, so for them `p` is the probability of True / shown.
  - `OneOf(augmentations, weights=None, p)`: picks one child per call with `random.choices` (`actual` = the index) and calls it, so in a `Compose` it picks per object; the picked child draws its own `p`, unpicked ones don't run (no `otherwise`). Validation: empty list, weights length, negative or zero-sum weights. It can nest. `flatten(augmentations)` (next to `happens`, filtered out of the docs) lists each item and then its `augmentations`, depth first; `Compose.__call__` clears `results` over it, so nested children are cleared too.
  - `Chain(augmentations, p)`: calls each child with the one object, in order (each draws its own `p`); `actual` is the list of the children's `actual` (`getattr`, None when missing). Like `OneOf`, it has `augmentations`, so `flatten` reaches its children; skipped → children don't run, no `otherwise`.
  - `Translation`, `Rotation`, `Scale` (`AxisAugmentation`): each parameter is a number `v`, sampled from (-v, v), a `(low, high)` pair, or a `(low, high, step)` triple, one of low, low + step, ... high (`sample` in `bpy_augmentations.py`, with a small tolerance so float steps reach high; validated by `check_offset`). Translation is in blender units and rotation in degrees, both added; scale is in percent, multiplied. The sampled values are stored in `actual_x/y/z`.
  - `Visibility(p=0.5)`: shows the object in the render with probability `p`, otherwise hides it (`hide_render` both ways; `otherwise=None` leaves it unchanged; the viewport is untouched). The labels follow `hide_render`, and treat objects in a collection excluded from the view layer or with `hide_render` (or under one) as hidden too (`frame.in_render`): renders (masks, passes, AOVs, occlusion) do so themselves; `bboxes` leaves hidden group members out (all hidden → `None`, no truncation/IoU check); `keypoint_visible` ray casts on the viewport depsgraph, which still has render-hidden objects, so it casts again past them, and a keypoint on a hidden object is not visible.
  - `KeepAbove(surface, margin=0)`: lifts the object along world Z (via `matrix_world`, so parented objects work) until its lowest point is `margin` above the surface top where they overlap seen from above; never lowers it, and an object not over the surface isn't moved. It compares world-space evaluated meshes with vertical BVH ray casts both ways: object vertices against the surface top below them, and surface vertices against the object bottom above them, which catches surface peaks between the object's vertices (`rest_offset`, the signed move, None when not over the surface; `move_z` applies it).
  - `PlaceOn(surface, margin=0)`: the same `rest_offset`, applied up or down, so the object rests on the surface; not over it → not moved, `actual` 0. `actual` is the signed move. It calls `view_layer.update()` first, because earlier transforms leave `matrix_world` stale, and it must come after them in a `Compose`. `actual` is the lift (0 when not moved).
  - `Seed(node_group, p, otherwise)`: every unlinked INT input with identifier `Seed` (`seed_inputs`, nested groups once each) gets its own `random.randint(0, MAX_SEED)`; it ignores the object, like an absolute data path. `actual` is `{node name or "Group node/Node": seed}`.
  - `LookAt(target, distance, elevation, azimuth, roll, focal_length)`: places the object on a sphere around the target (object, list of objects → mean world bbox center, or point) and aims its -Z at it with Y up (`to_track_quat("-Z", "Y")`), then rolls around local Z. Each parameter is `(min, max)`, an exact number, or `None` (keep current; roll defaults to 0). It sets `matrix_world`, so parented cameras work. `focal_length` is cameras only.
  - `FocalLength(focal_length, target=None, keep_size=False)`: perspective cameras only. `keep_size` scales the camera-to-target vector by `new_lens / old_lens` (a dolly zoom). It is exact for a centered target at its center's depth.
  - `DepthOfField(target=None, f_stop=None, p=1.0)`: enables DoF and sets the f-stop; when skipped by `p`, the DoF settings are untouched, or DoF is turned off with `otherwise=False`. It sets `focus_distance` along the view axis to the target center (clearing `focus_object`), so it must run after `LookAt`/`FocalLength` in a `Compose`.
  - The camera augmentations report the lens and f-stop as read back from Blender (stored as float32), not the sampled double.
  - `MaterialSlot(slots, weights, p, otherwise)`: picks one of the object's own material slots (by index or material name, `slot_index`), sets every face's `material_index` to it (`foreach_set`, `mesh.update()`) and `active_material_index`, so later `active_material...` paths reach it; `actual` is the material name. Mesh objects only. No copies: sharing a material or mesh is up to the scene. The faces are recorded with `bpy_undo.record_material_indices` (an `array`).
  - `SimpleMaterial(material_id, hue, saturation, value, roughness, metallic)`: sets the Principled BSDF Base Color (through HSV), Roughness and Metallic to random values in absolute `(min, max)` ranges, all 0-1. `None` leaves a value unchanged. It changes the **material**, so every object using it is affected.
  - `Node(node, inputs, p)`: sets many inputs of one node (by data path, absolute or relative) at once. `inputs` is `{name or index: spec}`; each becomes a `NodeInput` (data path `<node>.inputs[<key>].default_value`, filtered out of the docs) that on every call reads the socket type (`socket_type`) and runs a `Number`/`Vector`/`Boolean`/`Menu` built by `input_augmentation` (cached per type). A plain spec is the main argument (`value_range`, `p` for Boolean, `options` for Menu, None = defaults); an `Input(value_range, options, weights, p, otherwise)` (validated in `__init__`, `arguments()` returns only what was given; `otherwise` defaults to `UNSET` so Boolean keeps its False default) or a dict with those keys gives several. ROTATION sockets (geometry nodes, an Euler in radians) use `Vector` too. Color (RGBA) bounds of a number or 3 values keep alpha (`color_bound`). `actual` is `{key: child actual}`; `augmentations` lists the `NodeInput`s, so `Compose` clears their `results` through `flatten`. Its own `p` skips every input, without `otherwise`. `Menu` without options also reads a group node's menu input, following the Group Input link (through reroutes and nested groups) to a Menu Switch (`socket_menu_options`). The per-input classes share `InputAugmentation` (`resolve(obj)` → data path and kind, augmentations cached per both); `NodeInput` has a fixed `data_path`.
  - `Modifier(modifier, inputs, p)`: the same for a geometry nodes modifier's inputs (data path of the modifier, relative or absolute). `ModifierInput` resolves on every call (`bpy_a.modifier_input`): the key is a name or index in the node group's interface inputs (`bpy_paths.modifier_inputs`, Geometry included; the kind from `socket_type` via `interface_kind`), the path `modifier_input_path` (5.x `.properties.inputs.<identifier>.value`, 4.x `["<identifier>"]`). In 4.x a menu input is an int id property: `Menu` maps names to ints through `id_properties_ui(key)` items (`id_property_menu`).
  - Data-path augmentations change any value by its path (shader node inputs, geometry nodes inputs, shape keys, light settings…). An absolute path ignores the object, so it can be called as `aug()`. Inside a `Compose` it runs once per object.
    - `Number(data_path, value_range)`: int or float, set to a random value in the `(min, max)` range, or one of min, min + step, ... max for `(min, max, step)` (`sample`, validated by `check_range`); ints are rounded.
    - `Vector(data_path, value_range)`: the same per component. Each bound is a number for all components or a per-component sequence, and `None` keeps that component, e.g. `((0, 0, 0, None), (1, 1, 1, None))` for RGB that keeps alpha.
    - `Boolean(data_path, p=0.5)`: True with probability `p`, otherwise False.
    - `Menu(data_path, options=None, weights=None)`: enum. With no `options`, it takes them from RNA `enum_items`, or for menu sockets from the Menu Switch node's `enum_items`; otherwise `options` is required.
- **state**: `with state.restoring():` sets back every value changed inside it when it ends, also on an exception. `bpy_undo` keeps a stack of `Journal`s (`open_journal` / `close_journal`); every write an augmentation makes goes through `bpy_undo.set_attr(owner, name, value)` / `set_item` (id properties, 4.x modifier inputs), which record the old value (`to_plain` copy) the first time each `(owner pointer, name)` changes in the innermost journal, or through `record_transforms(obj)` (all `TRANSFORM_PROPERTIES` as one entry, `rotation_mode` set back first; call it before `matrix_world` or in-place transform changes) and `record_material_indices(mesh)`. `bpy_paths.set_value` uses them, so every data-path augmentation is covered. `undo()` runs the restores last first and skips owners that were removed (`ReferenceError`). Without an open journal nothing is recorded. Nested blocks: the inner one sets its changes back at its end. `state.set(owner, name, value)` is the same write for the user's own code. **A new augmentation must write only through `bpy_undo`**, or `restoring()` won't set it back; `tests/test_state.py::test_restoring` checks every augmentation.
- **generating**: `Compose(steps, path, resolution)` generates one datapoint per call (`preview(factor)` at reduced resolution); it returns `False` when a step skips the datapoint. Files are `<path>/<index>...`, where the index is the next free leading number in the folder (`next_index`), so output can be resumed.
  - **Steps:** `BBox(classes, iou_deconflict=None, max_truncation=None, max_occlusion=None)`, `Pose(classes)`, `RotationMatrix(objects)`, `OutputField(name, data_path, objects=None)`, `CameraData()`, `Keypoints(points)`, `Render(file_format="PNG")`, `Background(weights=None, noise_size=(1, 8), images_path=None)`, `BBoxImage(file_format="PNG", line_width=2, show_class=True)`, `AOVToImage(names, file_format="OPEN_EXR", skip_empty=False)`, `Passes(names, file_format="OPEN_EXR", skip_empty=False)`, `Segmentation(classes, per="instance"|"class"|"both", skip_empty=False, full_masks=False)`, `SegmentationImage(file_format="PNG", opacity=0.5, line_width=2, show_class=True)`. Each step takes its own objects; `Compose` has none.
  - **Classes:** `classes` is `{class name: [instances]}`, where an instance is an object or a sublist of objects labeled as one (bbox = union of members, one mask). An `Instances(parent, of)` entry (duck-typed by `is_instances`: `parent` and `of`) expands per frame (`frame.instance_groups`, needs the frame, so `to_instances(classes, frame)`; without a frame it is only checked) into one group per top-level depsgraph instance of `parent` (`instance_members`: `persistent_id` is the path innermost first, padded with `INSTANCE_PATH_END`; its last entry is the top-level instance's `id` attribute when it has one (Distribute Points on Faces adds it), otherwise its index, so while reading, a temporary NODES modifier (`index_id_nodes`) sets `id` to the index; it is removed before any render, so `id`-based randomness is unchanged) whose sources meet `of`. A geometry instance (`instance_object` is the parent: Object Info without As Instance, or nodes after the instancing that edit the meshes, like Smooth by Angle) has no source object; its mesh keeps the source mesh's name, so `read_instance_members` finds the objects using a mesh of that name, and `None` when none does; `instance_groups` raises when `of` matched nothing and some instance has no source. The group holds `InstanceMember`s that stand in for objects (`name`, `type`, `matrix_world`, local `coords` read during the depsgraph iteration, `parent`, `source`, `top`); `in_render` follows the parent. Groups with members can't use the Workbench or Object Index renders (instances share their source's color and pass index), so `frame.ids` / `full_ids` use `render_instance_ids`: Cycles, 1 sample, BOX filter, emission `material_override` (`instance_id_material`) showing the INSTANCER attribute `blendmentation_id` written by a temporary NODES modifier on each parent (`instance_id_nodes`: Sample Index on a temporary LUT mesh object, -1 for unlabeled instances; with `hide_others` it deletes them and the parent's own geometry) or, for plain objects, the OBJECT custom property; with `hide_others` everything without an id is transparent, because hiding a source with `hide_render` also hides its instances in 4.0. In 4.0, nodes keep a socket per data type under one name, so `socket()` picks the enabled one. `to_instances` flattens it to `(class, [objects])` pairs and rejects non-dicts, non-list values, empty sublists and objects in two instances. A class value can also be `{"instances": [...], "iou_deconflict": ..., "max_truncation": ..., "max_occlusion": ...}` (`split_class`); `class_settings` merges these over the `BBox` arguments, the class winning even when it sets None. Segmentation ignores them. For IoU, a pair conflicts when its IoU is over the lower of the two classes' limits (`iou_conflict`). `max_occlusion` (`occlusions`) is 1 - an instance's pixels in the normal id render / its pixels in an id render with every object outside the classes hidden (`hide_render`, restored), so only non-class objects occlude; it runs after the cheap checks and only when some class has a limit.
  - **Stages:** each step class has a `stage`, and `Compose` sorts by it, so list order doesn't matter. Label steps (0) run first, so a `BBox` skip happens before the beauty render (`max_occlusion` needs two Workbench id renders); then `Background` (1), `Render` (2), `AOVToImage`/`Passes`/`BBoxImage` (3), `Segmentation` (4), `SegmentationImage` (5).
  - **`prepare(frame)`:** runs for all steps after the `Frame` is created and before any step runs. It is for settings that must be in place before the beauty render (e.g. `Passes` enabling `use_pass_*`). Change them with `frame.set(owner, name, value)`, which records the old value; `generate` restores it in a `finally`.
  - **`check()`:** steps define `check()`, which runs before anything is generated, so bad config (classes format, file format, missing AOV, Workbench + AOVs, relative `OutputField` without objects) fails without wasting a render.
  - **`Frame`:** `bpy_generating.generate` builds a `Frame` and passes it to each step. It holds the scene, index, the `label` dict (`frame.add(key, entries)` appends to a list, so several steps can add to it), a lazy `beauty()` that renders with the scene engine **at most once**, and a lazy `multilayer()` that saves that render once as a multilayer EXR in the frame's temp dir, returning the path and each EXR part's channel names. `Render` writes the image through it (`write_still`), and `AOVToImage` reuses that Render Result, or triggers the one render itself when there is no `Render`. A new step that needs the beauty render must call `frame.beauty()`, not `bpy.ops.render.render()`.
  - **Label JSON:** written only when there is more than the image (e.g. `Render()` alone writes no JSON). It holds:
    - `resolution`, `image`, `aovs: {name: file}`, `passes: {name: file}`;
    - `bboxes: [{class, objects, bbox}]`;
    - `masks: [{class, objects, mask, per}]`, with instance masks `<index>_mask_<class>_<n>.png` (n counts instances through all classes and `Segmentation` steps of the datapoint) first, then class masks `<index>_class_<class>.png` (name sanitized); a taken file name gets `_2`, `_3`, ... (`save_masks` gets the earlier steps' entries as `previous`);
    - `skip_empty=True` (`Segmentation`, `AOVToImage`, `Passes`) doesn't write an all-zero image (masks: no pixel; layers: every non-alpha channel 0, `layer_empty`) and stores `None` as its file. The datapoint is kept. Code reading these files must handle `None` (`segmentation_image` skips them, COCO export skips the instance);
    - `full_masks: [{class, objects, mask}]` (`<index>_mask_<class>_<n>_full.png`, n counting full masks through the steps), with `full_masks=True`;
    - `rotation_matrices: [{object, rotation_matrix}]` (Blender camera axes);
    - `poses: [{class, objects, R, t, scale}]`: the first object's pose in OpenCV camera axes (`BLENDER_TO_OPENCV`, as `extrinsics_opencv`), `t` in Blender units, scale removed from `R` and saved; all members hidden → `None`s;
    - `background: {mode, color | noise_size | image}`;
    - `OutputField` values: absolute paths as one value, relative paths as `{object name: value}`;
    - `custom_dict` keys.
  - **Field values:** `OutputField` converts values with `to_json`: IDs become their names, and vectors/matrices become nested lists.
  - **Bboxes** are pixel `[x_min, y_min, x_max, y_max]` with a top-left origin, computed from the evaluated mesh vertices (modifiers included; occlusion ignored; `None` when out of frame). `max_truncation` measures the fraction of the unclipped box (`view_bounds`) outside the frame; any vertex behind the camera counts as fully truncated.
  - **Passes:** `save_layer` extracts one AOV or pass from `frame.multilayer()`. Channels are `<view layer>.<layer>.<channel>`. Index passes are `IndexOB`/`IndexMA` in 4.x and `Object Index`/`Material Index` in 5.x, so `PASSES` lists both names. OpenEXR always stores channels alphabetically (`A,U,V`), so they're sorted by `CHANNEL_ORDER` for PNG output.
  - **Preview images** (`BBoxImage`, `SegmentationImage`): draw the `bboxes` / `masks` of the labels on `frame.beauty_pixels()`, a color-managed 8-bit RGBA copy of the Render Result saved once to the temp dir (each call returns a new array), to `<index>_bboxes.<ext>` / `<index>_segmentation.<ext>`, label keys `bbox_image` / `segmentation_image`. Class colors (`CLASS_COLORS`) follow first appearance in the labels. Class names use the 3x5 `FONT` in numpy, because Blender's OpenImageIO has no FreeType and `blf` can't draw to images in 4.0 / module mode. `Compose` raises if the source step (`BBox` / `Segmentation`) is missing.
  - **`replace_render()`:** The Workbench id render replaces the beauty Render Result, so `frame.ids(groups, hide_others)` calls `frame.replace_render()` before rendering. It caches the id image per groups and `hide_others`, so `Segmentation` (outside Cycles) reuses the one `BBox(max_occlusion=...)` rendered for the same classes. It caches `beauty_pixels()` when a step set `frame.keep_beauty` in `prepare` (`SegmentationImage`), and marks the beauty as not rendered. A new step with its own render must do the same.
  - **Background:** picks a mode (`BACKGROUND_MODES`: `color`, `white_noise`, `color_noise`, `image`) by `weights` (`{mode: weight}`, left out = 0; None = equal, `image` only with `images_path`) with `random`, and a numpy rng seeded from `random.getrandbits`, so `random.seed` covers it. It sets `frame.background`, an 8-bit sRGB `(h, w, 3)` array (images: scaled to cover, random crop; folder listed once in `check()`, recursively). `check()` raises unless `film_transparent` and `image_settings.color_mode == "RGBA"`. `beauty_pixels()` composites over it (OpenImageIO premultiplies PNG alpha on read, so `rgb + bg * (1 - a)`), so the previews get it. With a background, `Render` writes through OpenImageIO as opaque RGB instead of `write_still`: PNG/JPEG from `beauty_pixels()` (8-bit, JPEG at the scene quality), EXR from `frame.beauty_float()` with the background converted sRGB → linear. Masks, AOVs and passes are unaffected.
  - **Full masks** (`full_masks`): each instance's silhouette with every other object hidden. `full_mask_packs` groups instances whose projected boxes (`view_bounds`, plus `PACK_MARGIN` px) don't overlap into one render; non-mesh-like types (`PACKABLE_TYPES`) or instances partly behind the camera get their own, hidden or out-of-frame ones none (empty mask). `frame.full_ids` renders a pack: Cycles via `render_index_ids` (1 sample, no denoising, Object Index pass, everything restored), other engines via `frame.ids(groups, hide_others=True)`, shared with `max_occlusion`. The visible masks are read first, since the full renders replace the beauty.
  - **CameraData:** `intrinsics` K follows Blender's sensor fit / shift / pixel-aspect rules; `extrinsics_opencv` flips Blender's camera axes (looks down -Z, Y up) to OpenCV's. `unit_scale` is the scene's meters per Blender unit (the Depth pass is depth along the view axis in Blender units, in Cycles and EEVEE). `depth_of_field` reports the effective `focus_distance` (with a focus object, the distance along the view axis to it, or to its `focus_subtarget` bone, as Blender computes it).
  - **Keypoints:** they are located on the evaluated mesh (deformations included) and projected with `world_to_camera_view`. Visibility is a `scene.ray_cast` from the camera, with a small tolerance so a point on a surface isn't hidden by that surface.
  - Render resolution and output settings are restored after each datapoint.

  Segmentation in Cycles (`prepare_segmentation` / `index_pass_ids`) reads the Object Index pass of the beauty render (`frame.multilayer()`, no extra render): `prepare` enables `use_pass_object_index` and sets every instance's `pass_index` to its id and all other editable objects' to 0 (`frame.set`, restored). The pass is not anti-aliased and respects `pass_alpha_threshold`, so alpha-clipped materials and shader displacement are right; volumes aren't in it. `frame.index_groups` records which groups own the pass ids; a second `Segmentation` with other groups, more than `MAX_PASS_INDEX` (32767) instances, or any other engine uses the Workbench render. `max_occlusion` always uses Workbench.

  Segmentation outside Cycles (`render_ids` / `save_masks`) is a separate Workbench render:
  - flat `OBJECT` color shading, no anti-aliasing, transparent film, compositor off;
  - every instance colored with its id encoded as `R = id % 256 / 255`, `G = id // 256 / 255`, saved as a float EXR and read back exactly;
  - all other objects, including ones not in `classes` (all of `bpy.data.objects`, to cover instanced collections) black, so they still occlude.

  Class masks are unions of the instance ids, so `per="both"` still needs one render. Masks hold only visible pixels; bboxes don't account for occlusion. All changed settings and object colors are restored afterwards.

  AOVs (`save_aovs`) avoid the compositor. The Render Result is saved via `save_render` as a multilayer EXR to a temp dir, and OpenImageIO splits out the channels named `<view layer>.<aov>.<channel>`, searching every EXR part (5.x writes one part per pass, 4.0 one part total). The engine must be Cycles or EEVEE.

- **export**: `export.coco/yolo/voc/bop(path, ...)` turn a generated folder's `<index>.json` labels into standard formats. It is pure Python with no `bpy` layer: `blendmentation/__init__.py` imports `bpy` only if it's available, and numpy / OpenImageIO are imported lazily, only for COCO masks, so YOLO and VOC run in a plain interpreter. Only labels with `"image"` are exported. Instances are keyed by `(class, objects)`, merging `bboxes` with masks where `"per": "instance"`. COCO segmentation is uncompressed RLE (column-major runs starting with zeros, as pycocotools expects); instances with empty masks are skipped. Class ids follow first appearance unless `classes=` is given. COCO, YOLO and VOC take `bbox_from`: `"label"` (BBox boxes, amodal) or `"mask"` (`label_boxes`: extent of each instance mask's visible pixels; raises without instance masks, skips `None` and empty masks).
  - `bop` writes `<output>/<split>/<scene_id>/` (default `<path>/bop/train_pbr/000000`), image ids = datapoint indices, `obj_id` = class number from 1 (`obj_ids.json`), mm via the camera's `unit_scale`. It needs `poses` and `camera.intrinsics` in every label; when the dataset has masks, every visible pose needs an instance mask and a full mask (`mask_visib/`, `mask/`, `scene_gt_info.json` from them, `None` files as empty masks); `passes.Depth` becomes a 16-bit `depth/` PNG (background, ≥ `clip_end` and overflow → 0). `check_scales` raises when a class's scale varies, since BOP has one model per class. Without masks or depth it needs no numpy / OpenImageIO beyond the hard numpy dependency.

Intended loop (see `example.py`): for N datapoints, inside `with state.restoring():`, apply the augmentation `Compose`s and call the generating `Compose`.

## Version differences

- Blender 5 moved geometry nodes modifier inputs from id properties to `modifier.properties.inputs.Socket_2.value`, so data paths for them differ by version. On 4.x the path is `modifiers["GeoNodes"]["Socket_2"]`; on 5.x it is `modifiers["GeoNodes"].properties.inputs.Socket_2.value`.
- Geometry nodes menu sockets don't exist in 4.0. On 5.x, modifier menu inputs list their options via RNA.
- In Blender 4.0 the AOV Output node's AOV name is its `name` property (`aov_name` from 4.1), which shadows the node name, so `node.name` isn't its key in `node_tree.nodes`. Look nodes up by their collection key (`nodes.items()`), as `save_node_tree` does.
- Blender 5 needs `image_settings.media_type` set alongside `file_format` (`set_file_format` in `bpy_generating.py`).
- Blender 5.2 EEVEE bug: a VALUE AOV listed before a COLOR AOV in the view layer renders as 0 (Cycles is fine). Listing color AOVs first avoids it.
- Blender 5.2 warns that `Material.use_nodes` and light node trees are going away in Blender 6.
