# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Blendmentation is a Python library for generating synthetic, augmented training datasets (renders, passes, AOVs, segmentation masks and labels) from Blender scenes. It is modelled after torchvision/albumentations-style transforms: you compose augmentations, apply them to Blender objects, render, then restore the scene and repeat.

**Approach** (the README and docs home page say it too): the variation in a pipeline lives in the user's Blender scene, in shader and geometry nodes, and Blendmentation changes their values (`Number`, `Vector`, `Boolean`, `Menu`, `Node`, `Seed`). Prefer that over new special-purpose augmentations; the exceptions are shortcuts for common basic setups (`KeepAbove`, `PlaceOn`, `LookAt`, `PlaceOnCurve`, `SimpleMaterial`, `FocalLength`, `DepthOfField`), and the transforms, for simple scenes and small changes outside geometry nodes (cluttered scenes: geometry nodes). The generating step is not part of usual Blender workflows apart from the color render, so it does its work itself.

## Running

Packaging and the ruff config are in `pyproject.toml`; lint with `.venv/bin/ruff check .` (CI runs it; E501 at 120 columns, not in tests). The code depends on `bpy`, `mathutils`, `numpy` and `OpenImageIO` and is meant to run inside Blender's bundled Python (e.g. Blender's scripting tab, or `blender --background scene.blend --python example.py`). `example.py` shows the intended usage of every feature; its docstring lists the scene it expects. It adds its own folder to `sys.path`. Import the modules as a package (`from blendmentation import augmentations`: each subpackage's `__init__` star-imports its module, whose `__all__` is the public API; `from blendmentation.augmentations import augmentations` still works), because they import their `bpy_*` sibling relatively. `tests/test_api.py` checks the re-exports.

**Tests** are in `tests/` (pytest) and run with `bpy` as a Python module:
```sh
uv venv --python 3.13 .venv && VIRTUAL_ENV=.venv uv pip install -e ".[module,test,dev]"   # bpy 5.x
uv venv --python 3.11 .venv311 && VIRTUAL_ENV=.venv311 uv pip install "bpy==4.5.14" -e ".[module,test]"  # bpy 4.5
uv venv --python 3.11 .venv42 && VIRTUAL_ENV=.venv42 uv pip install "bpy==4.2.23" -e ".[module,test]"  # bpy 4.2, the minimum
.venv/bin/python -m pytest                      # all
.venv/bin/python -m pytest tests/test_generating.py::test_keypoints   # one test
```
Run the suite on all three. GitHub Actions (`.github/workflows/tests.yml`, on pushes to `main`/`dev` and PRs) runs it on Linux with Mesa's software EGL (Workbench works without a GPU) for bpy 5.x/3.13, 4.5.14/3.11 and 4.2.23/3.11, plus a no-`bpy` job on 3.11 and 3.12. `release.yml` builds and creates a GitHub release with the wheel and sdist when a `v<version>` tag matching `pyproject.toml` is pushed; the release notes are that version's section of `CHANGELOG.md` (extracted by `.github/scripts/release_notes.py`), and the release fails without one. It also attaches `blendmentation-addon-<version>.zip` (the `blendmentation` folder at the top, for Blender's Install from Disk). It does not publish to PyPI yet (the user decided against it for now). The install docs tell users to clone or `pip install git+https://github.com/mmaciejak/Blendmentation`, which is only right because `main` always holds the latest release. **Work on the `dev` branch**; `main` only moves on a release (bump the version on `dev`, in `pyproject.toml` and in `bl_info` in `blendmentation/__init__.py` (`tests/test_addon.py` checks they match), and turn `## [Unreleased]` in `CHANGELOG.md` into `## [<version>] - <date>` with a new empty `[Unreleased]` above it and updated compare links, fast-forward `main` to it, tag `v<version>`). The docs site deploys from `main`, so it shows the released version. The `dev` extra is `fake-bpy-module` (stub-only `bpy-stubs`, safe next to the real `bpy`), so Pylance/Pyright know the `bpy` types; check typing with `npx pyright --pythonpath .venv/bin/python <files>`. `conftest.py` resets to an empty factory scene (Workbench, Cycles at 1 CPU sample) with a camera at (0, -10, 0) looking along +Y before every test. The `cube` fixture's default size is 1 (half-extent 0.5), and `renders` records the engine of every render started. Without `bpy`, the conftest still loads and only the pure tests (export) run. Workbench and EEVEE need a GPU.

The minimum is Blender 4.2 LTS (Python 3.11). On this machine `Blender 4.app` is Blender 5.2 (`Blender.app` is 4.0, below the minimum), e.g. `"/Applications/Blender 4.app/Contents/MacOS/Blender" -b --factory-startup --python-exit-code 1 --python script.py`.

The code also runs with `bpy` as a plain Python module (`pip install bpy OpenImageIO`; `bpy` 5.1+ needs Python 3.13, 4.2–5.0 need 3.11). Two things keep that working:
- `blendmentation/__init__.py` imports `bpy` first (if it's installed), because `mathutils` is only importable after `bpy` in module mode. Without `bpy`, the `augmentations`, `generating` and `state` subpackages call `require_bpy()` in their `__init__`, which raises an `ImportError` explaining how to get Blender; `export` works.
- Packaging: `numpy` is the only hard dependency. Blender bundles it with pip metadata, so installing into Blender's Python downloads nothing. `bpy` and OpenImageIO are bundled too but invisible to pip, so they are in the `module` extra; a hard dependency would install a second copy into Blender. Installing into Blender with `pip --target` (the user `scripts/modules` folder) needs `--no-deps`, or it installs a numpy that shadows Blender's.
- The package is also a legacy Blender add-on (not a 4.2+ extension, whose module would be `bl_ext.<repo>.blendmentation`, so scripts couldn't `import blendmentation`): `bl_info` and `register()` / `unregister()` in `__init__.py`, which import `blendmentation/addon.py` only when called, so a plain import registers nothing and module mode is unaffected. Installed, it lands in `scripts/addons/`, which is on `sys.path`. `addon.py` has `NODE_OT_blendmentation_copy_template` (`node.blendmentation_copy_template`, `copy_template` → `window_manager.clipboard`) and `OBJECT_OT_blendmentation_copy_shape_keys_template` (`object.blendmentation_copy_shape_keys_template`, polls for shape keys), `OBJECT_OT_blendmentation_copy_modifier_template` (`object.blendmentation_copy_modifier_template`, the active modifier), both with a `relative` property, drawn as Relative / Absolute buttons in the Blendmentation sidebar tabs (`NODE_PT_blendmentation`, `VIEW3D_PT_blendmentation`). The node one is also in `NODE_MT_node` (so F3 menu search finds it; F3 only lists operators in menus) and `NODE_MT_context_menu`, as two entries. `AddonPreferences` has the `prefix` (default `augmentations.`; `template_prefix` falls back to it when registered by hand). Checked headless with `addon_install` + `addon_utils.enable` under a scratch `BLENDER_USER_SCRIPTS`, and the operator in the app with a `temp_override` on an area switched to the Shader Editor.
- The `bpy` wheel ships numpy but not OpenImageIO, so `generating/bpy_images.py` (imported by `bpy_generating.py`) raises an `ImportError` with install instructions when it's missing.

## Architecture

Each subpackage under `blendmentation/` is split into two layers:

- **Public API module** (`augmentations.py`, `generating.py`, `state.py`): user-facing classes that only hold configuration and delegate the actual work. Only the main arguments are positional; options (`p`, `otherwise`, `data_path`, `name`, settings) come after a `*`, so new ones can be added anywhere.
- **`bpy_*` module** (`bpy_augmentations.py`, `bpy_generating.py`): plain functions that do the real Blender (`bpy`) manipulation. The public classes call these via a module alias (`bpy_a`, `bpy_g`). `state.py` uses the shared `blendmentation/bpy_undo.py`.

Keep this split: Blender-specific logic goes in the `bpy_*` modules, and the public classes stay thin. `blendmentation/bpy_paths.py` is shared by augmentations and generating. It parses data paths like `bpy.data.materials["Mat"].node_tree.nodes["X"].inputs[2].default_value` into attribute/item steps without `eval`, then gets or sets the value and calls `update_tag()` on the owning datablock. Paths starting with `bpy.` are absolute; any other path is relative to an object. `blendmentation/bpy_camera.py` has `focus_distance` (Blender's effective focus distance), shared by `DepthOfField` and `CameraData`. `blendmentation/values.py` (no `bpy`) has the value checks every subpackage uses: `is_number` (not `bool`) and `is_point` (a list or tuple of 3 numbers).

The subpackages:

- **augmentations**: `Compose` applies a list of transforms to each object in a list. Every transform is a callable taking a single `bpy` object, and it **mutates in place**.
  - The public classes are type-hinted with the aliases at the top of `augmentations.py` (`Offset`, `RangeOrValue`, `Target`, `Bound`); `bpy.types.Object` is imported under `TYPE_CHECKING` only, with `from __future__ import annotations`, so nothing extra is imported at runtime.
  - Every transform subclasses `Augmentation`, takes `p` (probability it runs, default 1 (0.5 for `Boolean`, `Visibility`, `ShadowCatcher`), drawn per call, so per object in a `Compose`) and implements `apply(obj)`; `__call__` draws `p`, sets `applied`, and on a skip calls `skip()`, which sets `actual` (or `actual_x/y/z`) to `None`, or, when `otherwise` is not None, calls `set_otherwise(obj)` and stores what it set. `Number`, `Vector`, `Boolean`, `Menu`, `Visibility`, `ShadowCatcher`, `FocalLength` (not with `keep_size`) and `DepthOfField` (`False` only: DoF off, `disable_depth_of_field`) take `otherwise`, validated in `__init__` (`check_otherwise`); the data-path ones set it by calling their sampler with `(v, v)`. A `Compose` skipped by its own `p` doesn't set `otherwise`. `p=1` draws no random number. `Compose` also takes `p`, drawn once per call. A call can override `p`, for a `Compose` (`compose(objects, p=0.5)`) and for any augmentation (`aug(obj, p=0.5)`, `aug(p=0.5)`). `Boolean`, `Visibility` and `ShadowCatcher` default to `otherwise=False`, so for them `p` is the probability of True / shown / a shadow catcher.
  - `results` / `_applied` (each call's `applied`, so a pick and an `otherwise` value can be told apart) are keyed by `_result_key(obj)`: the object's name, or None when `ignores_object` (absolute data path, `Seed`, `Node`/`Modifier` with an absolute path and their inputs, a `OneOf`/`Chain` of only those), so a `Compose` over several objects, which runs them once per object on the same value, leaves only the last; `ObjectAugmentation` with `data_path` ignores the object too but keys by its target's name. `Compose` clears both through `flatten` and stores `_objects` (the names it was called with).
  - `name` (optional, `check_name`: a non-empty string) is the last argument of every augmentation and `Compose`, stored by the base `__init__`; the graph shows it as `name` (left out of `settings`), the stats return it and the report uses it as the card title.
  - The graph: `augmentations/graph.py` (plain Python, duck-typed, no import of the classes) builds `Compose.describe()` and `graph.record(compose, id)` from two hooks on the classes: `_graph_children()` → `[(child, share)]` (`OneOf`: weight shares, `weight_shares`; `Compose`, `Chain`, `Node`/`Modifier` → their inputs, `InputAugmentation` → its augmentation: 1) and `_graph_values()` → `[(value, share)]` or None (`Menu`/`MaterialSlot`/`UVMap` with options listed, `Boolean`/`Visibility`/`ShadowCatcher` → True). Ids are the root id then child indices joined by dots; `reached` × `p` = `applied`, children get `applied × share`, rounded to 12 digits; `otherwise` and `values` (with the otherwise value merged in); settings from `vars()` minus state and anything holding an augmentation, as `plain` values (`weights` included, left out when None). The children of a node with `weights` (a `OneOf`) get `weight` (1 each without) and `share`, which the report shows in a box on the middle of their edges. An instance used twice is described once (`used_at`), later as `same_as`, and `record` writes it at its first id only. Plain callables in a `Compose` get `type`/`name` only.
  - `ObjectAugmentation` (filtered out of the docs): the base of the augmentations that change an object (`AxisAugmentation`, `Visibility`, `ShadowCatcher`, `KeepAbove`, `PlaceOn`, `LookAt`, `PlaceOnCurve`, `FocalLength`, `DepthOfField`, `MaterialSlot`, `UVMap`, `SimpleMaterial`). Their optional last argument `data_path` (absolute, `check_object_path`) makes `__call__` replace the object with `bpy_a.object_at(data_path)` (a `TypeError` when it isn't an `Object`) before the usual `p` draw, so a `Compose`'s objects are ignored, `aug()` works, and `results` is keyed by that object's name.
  - `OneOf(augmentations, weights=None, p)`: picks one child per call with `random.choices` (`actual` = the index) and calls it, so in a `Compose` it picks per object; the picked child draws its own `p`, unpicked ones don't run (no `otherwise`). Validation: empty list, weights length, negative or zero-sum weights. It can nest. `flatten(augmentations)` (next to `happens`, filtered out of the docs) lists each item and then its `augmentations`, depth first; `Compose.__call__` clears `results` over it, so nested children are cleared too.
  - `Chain(augmentations, p)`: calls each child with the one object, in order (each draws its own `p`); `actual` is the list of the children's `_result()` (what `results` stores, `(x, y, z)` for the axis ones; `actual` for other callables, None when missing). Like `OneOf`, it has `augmentations`, so `flatten` reaches its children; skipped → children don't run, no `otherwise`.
  - `Translation`, `Rotation`, `Scale` (`AxisAugmentation`): each parameter is a number `v`, sampled from (-v, v), a `(low, high)` pair, or a `(low, high, step)` triple, one of low, low + step, ... high (`sample` in `bpy_augmentations.py`, with a small tolerance so float steps reach high; validated by `check_offset`). Translation is in blender units and rotation in degrees, both added; scale is in percent, multiplied. The sampled values are stored in `actual_x/y/z`.
  - `Visibility(p=0.5)`: shows the object in the render with probability `p`, otherwise hides it (`hide_render` both ways; `otherwise=None` leaves it unchanged; the viewport is untouched). The labels follow `hide_render`, and treat objects in a collection excluded from the view layer or with `hide_render` (or under one) as hidden too (`frame.in_render`): renders (masks, passes, AOVs, occlusion) do so themselves; `bboxes` leaves hidden group members out (all hidden, or no vertices at all, e.g. a parent outputting only instances → `None`, no truncation/IoU check); `keypoint_visible` ray casts on the viewport depsgraph, which still has render-hidden objects, so it casts again past them, and a keypoint on a hidden object is not visible.
  - `ShadowCatcher(p=0.5, otherwise=False)`: sets `is_shadow_catcher` both ways (`bpy_a.shadow_catcher`), like `Visibility`. Only Cycles renders it; labels are unchanged (the object still occludes in the id renders and is index 0 in the Object Index pass).
  - `KeepAbove(surface, margin=0)`: lifts the object along world Z (via `matrix_world`, so parented objects work) until its lowest point is `margin` above the surface top where they overlap seen from above; never lowers it, and an object not over the surface isn't moved. It compares world-space evaluated meshes (`world_mesh`: every depsgraph instance whose parent is the object, plus its own mesh, as `loop_triangles`, so geometry nodes / collection instances count and non-flat faces bend along Blender's diagonal) with vertical BVH ray casts both ways: object vertices against the surface top below them, and surface vertices against the object bottom above them, which catches surface peaks between the object's vertices; then, at that height, `BVHTree.overlap` finds the triangle pairs cutting through each other and `edge_crossings` lifts by what their edges need where they cross in XY (a stick across a ridge), repeated `CROSSING_ROUNDS` times (`rest_offset`, the signed move, None when not over the surface). The gap is piecewise linear, so vertices + crossings make it exact. `settle` applies it with `move_z`, and for objects whose shape may follow the move (`shape_may_follow`: modifiers, instancing, or drivers on the object, its data or its shape keys) measures again and corrects with secant steps (`SETTLE_STEPS`, `SETTLE_TOLERANCE`), since geometry nodes can read the object's position.
  - `PlaceOn(surface, margin=0)`: the same `rest_offset`, applied up or down, so the object rests on the surface; not over it → not moved, `actual` 0. `actual` is the signed move. It calls `view_layer.update()` first, because earlier transforms leave `matrix_world` stale, and it must come after them in a `Compose`. `actual` is the lift (0 when not moved).
  - `Seed(node_group, p, otherwise)`: every unlinked INT input with identifier `Seed` (`seed_inputs`, nested groups once each) gets its own `random.randint(0, MAX_SEED)`; it ignores the object, like an absolute data path. `actual` is `{node name or "Group node/Node": seed}`.
  - `LookAt(target, distance, elevation, azimuth, roll, focal_length)`: places the object on a sphere around the target (object, list of objects → mean world bbox center, or point) and aims its -Z at it with Y up (`to_track_quat("-Z", "Y")`), then rolls around local Z. Each parameter is `(min, max)`, an exact number, or `None` (keep current; roll defaults to 0). It sets `matrix_world`, so parented cameras work. `focal_length` is cameras only.
  - `PlaceOnCurve(curve, align=False, position=(0, 1))`: moves the object to a point a fraction `position` (validated by `check_fraction`) of the curve's length from its start, uniform by length. `curve_segments` reads the evaluated curve as a mesh: Blender converts each spline to a chain of edges in its order and direction (cyclic ones close to their first vertex), so the edges in index order are the path; bevel, extrude and 2D fill are switched off (plain `setattr`, set back in a `finally`) while it is read, and a curve that evaluates to faces raises. Without `align` only `matrix_world.translation` changes; with it, -Z follows the segment direction with Y up (`to_track_quat("-Z", "Y")`), scale kept. It calls `view_layer.update()` first. `actual` is `{position, location}`. `LookAt` without distance/elevation/azimuth after it keeps the point and only aims.
  - `FocalLength(focal_length, target=None, keep_size=False, size=None)`: perspective cameras only. `keep_size` scales the camera-to-target vector by `new_lens / old_lens` (a dolly zoom), and with `size` (percent of the target's size before, range or number, validated in `__init__`, only with `keep_size`) also divides it by `size / 100`; `actual` has `size` (100 without). It is exact for a centered target at its center's depth.
  - `DepthOfField(target=None, f_stop=None, p=1.0)`: enables DoF and sets the f-stop; when skipped by `p`, the DoF settings are untouched, or DoF is turned off with `otherwise=False`. It sets `focus_distance` along the view axis to the target center (clearing `focus_object`), so it must run after `LookAt`/`FocalLength` in a `Compose`. `defocus` (an `Offset` in percent, `check_offset`, `sample`) multiplies that distance by `1 + percent / 100` (not below 0), or without a target the scene's effective focus (`bpy_camera.focus_distance`, shared with `CameraData`; a focus object is then cleared); `actual` gets `defocus`.
  - The camera augmentations report the lens and f-stop as read back from Blender (stored as float32), not the sampled double.
  - `MaterialSlot(slots, weights, p, otherwise)`: picks one of the object's own material slots (by index or material name, `slot_index`), sets every face's `material_index` to it (`foreach_set`, `mesh.update()`) and `active_material_index`, so later `active_material...` paths reach it; `actual` is the material name. Mesh objects only. No copies: sharing a material or mesh is up to the scene. The faces are recorded with `bpy_undo.record_material_indices` (an `array`).
  - `UVMap(uv_maps, weights, p, otherwise)`: picks one of the mesh's UV maps (by index or name, `uv_map_index`) and sets its `active_render` and `active`; `actual` is its name. Setting either flag to False does nothing, so the layers that had them are recorded with `set_attr(layer, flag, True)` before the picked one is set: restoring sets them back last. Mesh objects only; the UV maps belong to the mesh, so objects sharing it share the pick.
  - `SimpleMaterial(material_id, hue, saturation, value, roughness, metallic)`: sets the Principled BSDF Base Color (through HSV), Roughness and Metallic to random values in absolute `(min, max)` ranges (or exact values, `range_or_value`), all 0-1. `None` leaves a value unchanged. It changes the **material**, so every object using it is affected.
  - `Node(node, inputs, p)`: sets many inputs of one node (by data path, absolute or relative) at once. `inputs` is `{name or index: spec}`, where a spec is a `Number`/`Vector`/`Boolean`/`Menu` **without a data path** (they all subclass `PathAugmentation`; `split_path` takes a non-string first argument as the main one: `value_range`, `p` for Boolean, `options` for Menu; `path()` raises without a path) or, for short, that main argument alone. Each becomes a `NodeInput` (data path `<node>.inputs[<key>].default_value`, filtered out of the docs) that on every call reads the socket type (`socket_type`), checks the augmentation's class against it (`INPUT_AUGMENTATIONS`: VALUE/INT → Number, VECTOR/ROTATION/RGBA → Vector, BOOLEAN → Boolean, MENU → Menu; else `TypeError`), sets its `data_path` (and `color` for RGBA, so `Vector.bounds` keeps alpha via `color_bound`), calls it, and sets `data_path` back to None. A plain spec becomes an augmentation built by `input_augmentation`, cached per socket type. An augmentation with its own path is a `ValueError`, any other augmentation a `TypeError`. `actual` is `{key: child actual}`; `augmentations` lists the `NodeInput`s, and each `NodeInput.augmentations` its augmentation, so `Compose` clears their `results` through `flatten`. Its own `p` skips every input, without `otherwise`. `Menu` without options also reads a group node's menu input, following the Group Input link (through reroutes and nested groups) to a Menu Switch (`socket_menu_options`). `Node` and `Modifier` share `InputsAugmentation` (the empty-inputs check and `apply`). The per-input classes share `InputAugmentation` (`resolve(obj)` → data path and kind); `NodeInput` has a fixed `data_path`.
  - `Node.template(node, obj=None, prefix, relative=False)` (static, → `bpy_a.node_template`): source text of a `Node` for a node or its data path (a path is kept as given; a node gets `node_path`, its `repr` with double-quoted keys, or with `relative` `relative_node_path` from `obj`: itself, `data`, `active_material`, `material_slots[i].material` or a NODES modifier's `node_group`; a world's node is relative to the world). It starts with `template_header`, two comment lines saying relative (the object's name and `compose([<its path>])`) or absolute (what it changes). Every enabled input (not `NodeSocketVirtual`) is written as its class without a path (`template_input`): numbers `Number`, vectors `Vector`, with `(min, max)` from `socket_limits` (a group node's interface `min_value`/`max_value`, else the socket class's RNA `hard_min`/`hard_max`, e.g. 0-1 for factors; per-socket declared limits of built-in nodes aren't readable from Python), and `(v, v)` with the current value when a limit is ≥ `UNBOUNDED` (the ±3.4e38 / ±2³¹ "no limit" defaults); rotation `Vector((v, v))`, color `Vector((0.0, 1.0))`, `Boolean(p=0.5)`, `Menu([every option])` (`socket_menu_options`; a built-in node's menu, whose options Python can't list, is a `Warning!` comment). Linked, `hide_value` (Normal) and unsupported sockets are comments; names used twice are keyed by index. Comments give type and current value, aligned up to `TEMPLATE_ALIGN` chars. The add-on's operator copies it.
  - `Chain.shape_keys_template(obj, prefix, relative=True)` (→ `bpy_a.shape_keys_template`): a `Chain` with a `Number` over each shape key's slider range, relative paths (`data.shape_keys.key_blocks[...]`) or absolute through the object; the basis is skipped, muted and driven keys are comments, non-relative shape keys raise. Same header and alignment (all lines).
  - `Modifier.template(modifier, obj=None, prefix, relative=True)` (→ `bpy_a.modifier_template`): the same for any modifier (or its path). Geometry nodes (`node_modifier_rows`): every interface input but Geometry, limits from the interface item (`interface_limits`), menu options via `id_property_menu` (4.x, value mapped back to the name) or `menu_options` (5.x RNA), inputs reading an attribute (`modifier_input_used_attribute`) and unsupported sockets as comments. Other modifiers (`modifier_property_rows`): `modifier_properties` (writable number/vector/boolean/menu RNA properties, without `MODIFIER_UI` and `open_*` panels), keyed by identifier, the UI name in the comment, limits from `soft_min`/`soft_max`. A last comment hints `"show_render"`. Relative `modifiers["<name>"]` or absolute `node_path`. All three templates share `template_text` (layout), `template_entry` (one input) and `template_row`. The add-on's `OBJECT_OT_blendmentation_copy_modifier_template` copies it for `obj.modifiers.active`.
  - `Modifier(modifier, inputs, p)`: the same for a modifier (data path of the modifier, relative or absolute): a geometry nodes modifier's inputs by name or index, or any modifier's RNA settings by identifier (`levels`; on a NODES modifier only when no input has that name), kind from `property_kind` (FLOAT/INT → VALUE/INT, arrays VECTOR or RGBA, BOOLEAN, single-choice ENUM → MENU). `ModifierInput` resolves on every call (`bpy_a.modifier_input`): the key is a name or index in the node group's interface inputs (`bpy_paths.modifier_inputs`, Geometry included; the kind from `socket_type` via `interface_kind`), the path `modifier_input_path` (5.x `.properties.inputs.<identifier>.value`, 4.x `["<identifier>"]`). In 4.x a menu input is an int id property: `Menu` maps names to ints through `id_properties_ui(key)` items (`id_property_menu`).
  - Data-path augmentations change any value by its path (shader node inputs, geometry nodes inputs, shape keys, light settings…). An absolute path ignores the object, so it can be called as `aug()`. Inside a `Compose` it runs once per object.
    - `Number(data_path, value_range)`: int or float, set to a random value in the `(min, max)` range, or one of min, min + step, ... max for `(min, max, step)` (`sample`, validated by `check_range`); ints are rounded.
    - `Vector(data_path, value_range)`: the same per component. Each bound is a number for all components or a per-component sequence, and `None` keeps that component, e.g. `((0, 0, 0, None), (1, 1, 1, None))` for RGB that keeps alpha.
    - `Boolean(data_path, p=0.5)`: True with probability `p`, otherwise False.
    - `Menu(data_path, options=None, weights=None)`: enum. With no `options`, it takes them from RNA `enum_items`, or for menu sockets from the Menu Switch node's `enum_items`; otherwise `options` is required.
- **state**: `with state.restoring():` sets back every value changed inside it when it ends, also on an exception. `bpy_undo` keeps a stack of `Journal`s (`open_journal` / `close_journal`); every write an augmentation makes goes through `bpy_undo.set_attr(owner, name, value)` / `set_item` (id properties, 4.x modifier inputs), which record the old value (`to_plain` copy) the first time each `(owner pointer, name)` changes in the innermost journal, or through `record_transforms(obj)` (all `TRANSFORM_PROPERTIES` as one entry, `rotation_mode` set back first; call it before `matrix_world` or in-place transform changes) and `record_material_indices(mesh)`. `bpy_paths.set_value` uses them, so every data-path augmentation is covered. `undo()` runs the restores last first and skips owners that were removed (`ReferenceError`). Without an open journal nothing is recorded. Nested blocks: the inner one sets its changes back at its end. `state.set(owner, name, value)` is the same write for the user's own code. **A new augmentation must write only through `bpy_undo`**, or `restoring()` won't set it back; `tests/test_state.py::test_restoring` checks every augmentation. Settings Blendmentation changes only for a while (id renders, a datapoint's resolution and output, `curve_segments`) go through `with bpy_undo.temporary() as changes:` instead (`Temporary`: `set`, `set_many`, `set_item`, `save(owner, *names)` restored together in that order, `add(callback)` for removing temporary datablocks and modifiers; restored last first, also on an exception), not the journal.
- **generating**: the `bpy` layer is `bpy_generating.py` (classes, projection, `Frame`, the step functions, `generate`) and the modules it imports by name (`bpy_ids.render_ids(...)`): `bpy_images.py` (the OpenImageIO import, Render Result / EXR input and output, `PASSES`), `bpy_instances.py` (reading `Instances` from the depsgraph), `bpy_ids.py` (the id renders) and `drawing.py` (numpy only: preview drawing, `FONT`, `CLASS_COLORS`, background noise and compositing). `Compose(steps, path, resolution, prefix="")` generates one datapoint per call (`preview(factor)` at reduced resolution); it returns `False` when a step skips the datapoint. Files are `<path>/<prefix><index>...` (`frame.file_name`; `save_masks` gets that stem), where the index is the next free leading number after the prefix in the folder (`next_index(path, prefix)`), so output can be resumed and runs with other prefixes share a folder. The prefix (checked in `Compose.__init__`: a string, no `/` or `\`, not ending in a digit, which would run into the index) also starts the `Augmentations` graph file and `skipped.jsonl` (`frame.prefix`).
  - **Steps:** `BBox(classes, iou_deconflict=None, max_truncation=None, max_occlusion=None, allow_empty=False)`, `Pose(classes)`, `OutputField(name, data_path, objects=None)`, `CameraData()`, `Keypoints(points)`, `Augmentations(composes, graph_file="augmentations.json")`, `Render(file_format="PNG")`, `Background(weights=None, noise_size=(1, 8), images_path=None)`, `BBoxImage(file_format="PNG", line_width=2, show_class=True)`, `AOVToImage(names, file_format="OPEN_EXR", skip_empty=False)`, `Passes(names, file_format="OPEN_EXR", skip_empty=False)`, `Segmentation(classes, per="instance"|"class"|"both", skip_empty=False, full_masks=False)`, `SegmentationImage(file_format="PNG", opacity=0.5, line_width=2, show_class=True)`. Each step takes its own objects; `Compose` has none.
  - **Classes:** `classes` is `{class name: [instances]}`, where an instance is an object or a sublist of objects labeled as one (bbox = union of members, one mask). An `Instances(parent, of)` entry (duck-typed by `is_instances`: `parent` and `of`) expands per frame (`frame.instance_groups`, needs the frame, so `to_instances(classes, frame)`; without a frame it is only checked) into one group per top-level depsgraph instance of `parent` (`instance_members`: `persistent_id` is the path innermost first, padded with `INSTANCE_PATH_END`; its last entry is the top-level instance's `id` attribute when it has one (Distribute Points on Faces adds it), otherwise its index, so while reading, a temporary NODES modifier (`index_id_nodes`) sets `id` to the index; it is removed before any render, so `id`-based randomness is unchanged) whose sources meet `of`. A geometry instance (`instance_object` is the parent: Object Info without As Instance, or nodes after the instancing that edit the meshes, like Smooth by Angle) has no source object; its mesh keeps the source mesh's name, so `read_instance_members` finds the objects using a mesh of that name, and `None` when none does; `instance_groups` raises when `of` matched nothing and some instance has no source. The group holds `InstanceMember`s that stand in for objects (`name`, `type`, `matrix_world`, local `coords` read during the depsgraph iteration, `parent`, `source`, `top`); `in_render` follows the parent. Groups with members can't use the Workbench or Object Index renders (instances share their source's color and pass index), so `frame.ids` / `full_ids` use `render_instance_ids`: Cycles, 1 sample, BOX filter, emission `material_override` (`instance_id_material`) showing the INSTANCER attribute `blendmentation_id` written by a temporary NODES modifier on each parent (`instance_id_nodes`: Sample Index on a temporary LUT mesh object, -1 for unlabeled instances; with `hide_others` it deletes them and the parent's own geometry) or, for plain objects, the OBJECT custom property; with `hide_others` everything without an id is transparent, because hiding a source with `hide_render` can also hide its instances. `to_instances` flattens it to `(class, [objects])` pairs and rejects non-dicts, non-list values, empty sublists and objects in two instances. A class value can also be `{"instances": [...], "iou_deconflict": ..., "max_truncation": ..., "max_occlusion": ...}` (`split_class`); `class_settings` merges these over the `BBox` arguments, the class winning even when it sets None. Segmentation ignores them. For IoU, a pair conflicts when its IoU is over the lower of the two classes' limits (`iou_conflict`). `max_occlusion` (`occlusions`) is 1 - an instance's pixels in the normal id render / its pixels in an id render with every object outside the classes hidden (`hide_render`, restored), so only non-class objects occlude; it runs after the cheap checks and only when some class has a limit.
  - **Skips:** `bboxes` sets `frame.skip` (`{"reason", "class", "objects", "value", "limit"}`; `iou_conflict` returns the pair, so `class`/`objects` list both) before returning False; `generate` then calls `skipped(frame)` on every step (`Step` no-op, filtered out of the docs), and `Augmentations.skipped` appends `{"skip", "augmentations": record}` to `<path>/skipped.jsonl` (`SKIPPED_FILE`, `record_skip`) and writes the graph. `export.skip_stats` counts it by reason and class, `augmentation_stats` adds `skipped` counts per node and `skipped_observed` per value (`count_records` runs over kept and skipped records), and the report shows the count (click: reasons) and, per card, `skipRates`: how often the datapoint was skipped when the augmentation ran vs when it didn't, per object (from the kept and skipped counts), drawn by `skipBar` as a bar centered on 0, the change in the skip rate: red to the right (+) for more skips when it ran, green to the left (−) for fewer, half the bar = 50 points (`SKIP_SCALE`), faded unless a two-proportion z > 3; no bar when it always runs; per value in the panel.
  - **`Augmentations`** (stage 0, `record_augmentations`): takes augmentation `Compose`s (one → id `"0"`, a list → `"0"`, `"1"`..., a dict → its names, `augmentation_roots`) and sets `label["augmentations"]` to `graph.record` of each; writes `{"augmentations": [graph.describe(...)]}` to `<path>/<graph_file>` when the text differs (the file has no leading number, so `next_index` and the export ignore it).
  - **`Step`:** every step subclasses `Step` (filtered out of the docs), which has the no-op `check` and `prepare` that `generate` calls on every step; `Compose` raises a `TypeError` for anything else.
  - **Stages:** each step class has a `stage`, and `Compose` sorts by it, so list order doesn't matter. Label steps (0) run first, so a `BBox` skip happens before the beauty render (`max_occlusion` needs two Workbench id renders); then `Background` (1), `Render` (2), `AOVToImage`/`Passes`/`BBoxImage` (3), `Segmentation` (4), `SegmentationImage` (5).
  - **`prepare(frame)`:** runs for all steps after the `Frame` is created and before any step runs. It is for settings that must be in place before the beauty render (e.g. `Passes` enabling `use_pass_*`). Change them with `frame.set(owner, name, value)`, which records the old value in `generate`'s `Temporary` (`frame.changes`), restored with the resolution and the image settings (those saved first, so set back last, format first).
  - **`check()`:** steps define `check()`, which runs before anything is generated, so bad config (classes format, file format, missing AOV, Workbench + AOVs, relative `OutputField` without objects) fails without wasting a render.
  - **`Frame`:** `bpy_generating.generate` builds a `Frame` and passes it to each step. It holds the scene, index, the `label` dict (`frame.add(key, entries)` appends to a list, so several steps can add to it), a lazy `beauty()` that renders with the scene engine **at most once**, and a lazy `multilayer()` that saves that render once as a multilayer EXR in the frame's temp dir, returning the path and each EXR part's channel names. `Render` writes the image through it (`write_still`), and `AOVToImage` reuses that Render Result, or triggers the one render itself when there is no `Render`. A new step that needs the beauty render must call `frame.beauty()`, not `bpy.ops.render.render()`.
  - **Label JSON:** written only when there is more than the image (e.g. `Render()` alone writes no JSON). It holds:
    - `version` first (`blendmentation.__version__`, made from `bl_info`; custom keys can't replace it, and it alone doesn't make a label file; `skipped.jsonl` lines have it too), `resolution`, `image`, `aovs: {name: file}`, `passes: {name: file}`;
    - `bboxes: [{class, objects, bbox}]`;
    - `masks: [{class, objects, mask, per}]`, with instance masks `<index>_mask_<class>_<n>.png` (n counts instances through all classes and `Segmentation` steps of the datapoint) first, then class masks `<index>_class_<class>.png` (name sanitized); a taken file name gets `_2`, `_3`, ... (`save_masks` gets the earlier steps' entries as `previous`);
    - `skip_empty=True` (`Segmentation`, `AOVToImage`, `Passes`) doesn't write an all-zero image (masks: no pixel; layers: every non-alpha channel 0, `layer_empty`) and stores `None` as its file. The datapoint is kept. Code reading these files must handle `None` (`segmentation_image` skips them, COCO export skips the instance);
    - `full_masks: [{class, objects, mask}]` (`<index>_mask_<class>_<n>_full.png`, n counting full masks through the steps), with `full_masks=True`;
    - `poses: [{class, objects, R, t, scale}]`: the first object's pose in OpenCV camera axes (`BLENDER_TO_OPENCV`, as `extrinsics_opencv`), `t` in Blender units, scale removed from `R` and saved; all members hidden → `None`s;
    - `background: {mode, color | noise_size | image}`;
    - `OutputField` values: absolute paths as one value, relative paths as `{object name: value}`;
    - `custom_dict` keys.
  - **Field values:** `OutputField` converts values with `to_json`: IDs become their names, and vectors/matrices become nested lists.
  - **Bboxes** are pixel `[x_min, y_min, x_max, y_max]` with a top-left origin, computed from the evaluated mesh vertices (modifiers included; occlusion ignored; `None` when out of frame). `max_truncation` measures the fraction of the unclipped box (`view_bounds`) outside the frame; any vertex behind the camera counts as fully truncated. With `allow_empty`, instances out of view are ignored (`in_view`: clipped box, or, partly behind the camera, the bounding box cut at the near clip plane reaching the frame), so partial and negative samples are kept.
  - **Passes:** `save_layer` extracts one AOV or pass from `frame.multilayer()`. Channels are `<view layer>.<layer>.<channel>`. Index passes are `IndexOB`/`IndexMA` in 4.x and `Object Index`/`Material Index` in 5.x, so `PASSES` lists both names. OpenEXR always stores channels alphabetically (`A,U,V`), so they're sorted by `CHANNEL_ORDER` for PNG output.
  - **Preview images** (`BBoxImage`, `SegmentationImage`): draw the `bboxes` / `masks` of the labels on `frame.beauty_pixels()`, a color-managed 8-bit RGBA copy of the Render Result saved once to the temp dir (each call returns a new array), to `<index>_bboxes.<ext>` / `<index>_segmentation.<ext>`, label keys `bbox_image` / `segmentation_image`. Class colors (`CLASS_COLORS`) follow first appearance in the labels. Class names use the 3x5 `FONT` in numpy, because Blender's OpenImageIO has no FreeType and `blf` can't draw to images in module mode. `Compose` raises if the source step (`BBox` / `Segmentation`) is missing.
  - **`replace_render()`:** The Workbench id render replaces the beauty Render Result, so `frame.ids(groups, hide_others)` calls `frame.replace_render()` before rendering. It caches the id image per groups and `hide_others`, so `Segmentation` (outside Cycles) reuses the one `BBox(max_occlusion=...)` rendered for the same classes. It caches `beauty_pixels()` when a step set `frame.keep_beauty` in `prepare` (`SegmentationImage`), and marks the beauty as not rendered. A new step with its own render must do the same.
  - **Background:** picks a mode (`BACKGROUND_MODES`: `color`, `white_noise`, `color_noise`, `image`) by `weights` (`{mode: weight}`, left out = 0; None = equal, `image` only with `images_path`) with `random`, and a numpy rng seeded from `random.getrandbits`, so `random.seed` covers it. It sets `frame.background`, an 8-bit sRGB `(h, w, 3)` array (images: scaled to cover, random crop; folder listed once in `check()`, recursively). `check()` raises unless `image_settings.color_mode == "RGBA"` (`film_transparent` isn't required: an opaque render hides the background). `beauty_pixels()` composites over it (OpenImageIO premultiplies PNG alpha on read, so `rgb + bg * (1 - a)`), so the previews get it. With a background, `Render` writes through OpenImageIO as opaque RGB instead of `write_still`: PNG/JPEG from `beauty_pixels()` (8-bit, JPEG at the scene quality), EXR from `frame.beauty_float()` with the background converted sRGB → linear. Masks, AOVs and passes are unaffected.
  - **Full masks** (`full_masks`): each instance's silhouette with every other object hidden. `full_mask_packs` groups instances whose projected boxes (`view_bounds`, plus `PACK_MARGIN` px) don't overlap into one render; non-mesh-like types (`PACKABLE_TYPES`) or instances partly behind the camera get their own, hidden or out-of-frame ones none (empty mask). `frame.full_ids` renders a pack: Cycles via `render_index_ids` (1 sample, no denoising, Object Index pass, everything restored), other engines via `frame.ids(groups, hide_others=True)`, shared with `max_occlusion`. The visible masks are read first, since the full renders replace the beauty.
  - **CameraData:** `intrinsics` K follows Blender's sensor fit / shift / pixel-aspect rules, with OpenCV pixel centers at whole numbers (principal point `(W - 1) / 2` without shift, as BlenderProc; boxes and keypoints count from the image corner, COCO style), checked by `tests/test_export.py::test_bop_reads_back` (model through cam_R/cam_t/cam_K = full mask, depth = model Z); `extrinsics_opencv` flips Blender's camera axes (looks down -Z, Y up) to OpenCV's. `unit_scale` is the scene's meters per Blender unit (the Depth pass is depth along the view axis in Blender units, in Cycles and EEVEE). `depth_of_field` reports the effective `focus_distance` (with a focus object, the distance along the view axis to it, or to its `focus_subtarget` bone, as Blender computes it).
  - **Keypoints:** they are located on the evaluated mesh (deformations included) and projected with `world_to_camera_view`. Visibility is a `scene.ray_cast` from the camera, with a small tolerance so a point on a surface isn't hidden by that surface.
  - Render resolution and output settings are restored after each datapoint.

  Segmentation in Cycles (`prepare_segmentation` / `index_pass_ids`, both use `cycles_index(scene, groups)`) reads the Object Index pass of the beauty render (`frame.multilayer()`, no extra render), unless `bpy_ids.blurred(scene)` (motion blur or camera DoF): the pass keeps a pixel's first sample, at a random lens point / shutter time, so the masks would be speckled as wide as the blur; then `segmentation` uses `frame.index_ids(groups, hide_others=False)` (`render_index_ids` without hiding others) instead. Every Cycles id render (`render_index_ids`, `render_instance_ids`) calls `bpy_ids.sharpen(changes, scene)` (motion blur and DoF off). Masks are the sharp outline at the frame, like bboxes, poses and keypoints; `tests/test_generating.py::test_masks_sharp_with_blur` and `test_instances.py::test_instance_masks_sharp_with_depth_of_field` check it. Without blur: `prepare` enables `use_pass_object_index` and sets every instance's `pass_index` to its id and all other editable objects' to 0 (`frame.set`, restored). The pass is not anti-aliased and respects `pass_alpha_threshold`, so alpha-clipped materials and shader displacement are right; volumes aren't in it. `frame.index_groups` records which groups own the pass ids; a second `Segmentation` with other groups, more than `MAX_PASS_INDEX` (32767) instances, or any other engine uses the Workbench render. `max_occlusion` always uses Workbench.

  Segmentation outside Cycles (`render_ids` / `save_masks`) is a separate Workbench render:
  - flat `OBJECT` color shading, no anti-aliasing, transparent film, compositor off;
  - every instance colored with its id encoded as `R = id % 256 / 255`, `G = id // 256 / 255`, saved as a float EXR and read back exactly;
  - all other objects, including ones not in `classes` (all of `bpy.data.objects`, to cover instanced collections) black, so they still occlude.

  Class masks are unions of the instance ids, so `per="both"` still needs one render. Masks hold only visible pixels; bboxes don't account for occlusion. All changed settings and object colors are restored afterwards.

  AOVs (`save_aovs`) avoid the compositor. The Render Result is saved via `save_render` as a multilayer EXR to a temp dir, and OpenImageIO splits out the channels named `<view layer>.<aov>.<channel>`, searching every EXR part (5.x writes one part per pass, 4.x one part total). The engine must be Cycles or EEVEE.

- **export**: `export.coco/yolo/voc/bop(path, ...)` turn a generated folder's `<prefix><index>.json` labels into standard formats. `label_files(path, prefix=None)` lists them (`LABEL`: the prefix is everything before the trailing digits) sorted by prefix and index, all prefixes or only one; `load_labels` returns `(image id, label)`, the id being the index, or the position when any label has a prefix, so merged runs keep unique ids. `augmentation_stats`, `skip_stats` and `augmentation_report` take `prefix=""` and read only that run's labels, `<prefix><graph_file>` and `<prefix>skipped.jsonl` (the report defaults to `<prefix>augmentations.html`). It is pure Python with no `bpy` layer: `blendmentation/__init__.py` imports `bpy` only if it's available, and numpy / OpenImageIO are imported lazily, only for COCO masks, so YOLO and VOC run in a plain interpreter. Only labels with `"image"` are exported. Instances are keyed by `(class, objects)`, merging `bboxes` with masks where `"per": "instance"`. COCO segmentation is uncompressed RLE (column-major runs starting with zeros, as pycocotools expects); instances with empty masks are skipped. Class ids follow first appearance unless `classes=` is given. COCO, YOLO and VOC take `bbox_from`: `"label"` (BBox boxes, amodal) or `"mask"` (`label_boxes`: extent of each instance mask's visible pixels; raises without instance masks, skips `None` and empty masks). `yolo` writes `images.txt` (`YOLO_IMAGES`, `./<image>` per label) and `dataset.yaml` with `train`/`val` pointing at it, because Ultralytics takes every image in a folder (masks, previews) as a training image. `yolo(task="segment", tolerance=0)` writes one polygon per instance mask from `export/polygons.py` (numpy only, no OpenCV): `traced` follows the pixel edges (4-connected parts, clockwise with the mask on the right, holes have negative `signed_area` and are dropped), `pixel_indices` moves the outline onto the edge pixels' indices (as `cv2.findContours`), `cut_stairs` drops the inner stair corners (lossless, like `CHAIN_APPROX_SIMPLE`), `simplify` is Douglas-Peucker with distances to the segment (so out-and-back spikes keep their tip), `join` bridges the parts there and back (like Ultralytics' `merge_multi_segment`). Points are written at pixel centers (index + 0.5), because Ultralytics' `polygon2mask` truncates the scaled points to int32 before `cv2.fillPoly`; `polygons.draw` reproduces `fillPoly` for the tests. Checked once against OpenCV and Ultralytics (dataset loads, `polygon2mask` gives the mask, bridges aside).
  - `augmentation_stats(path, graph_file)` reads the graph and every label with `augmentations`: per node `calls` (the root `Compose`'s objects per datapoint; one per datapoint for `ignores_object` nodes, their last entry), `applied`, `observed`, `expected` (the graph's `applied`; None for `used_at` nodes and `ignores_object` ones whose `reached` differs from the root's `applied`, since per-object picks then decide the last call) and `values` (keyed by `json.dumps`, values set but not in the graph get `expected` None).
  - `write_report(output, title, path, roots, stats=None, datapoints=None)` fills the page; without stats it is a preview (`"preview": true`: bars filled to the graph's probability, no observed/difference). `augmentations.graph_preview(composes, path, show)` uses it with `graph.describe` of `compose_roots(composes)` (one, list or dict, shared with `generating.Augmentations`); a folder path gets `augmentations_preview.html`, `show` calls `webbrowser.open`. `augmentations.py` imports `..export.export` for it (export never imports augmentations).
  - `augmentation_report(path, output, graph_file)` fills `export/report.html` (package data in `pyproject.toml`; the add-on zip has the whole folder) by replacing `__DATA__` with `{title, path, datapoints, roots, stats}` (`</` escaped) and writes `<path>/augmentations.html`. The page is vanilla JS, no CDN, a flowchart: `measure` gives each node a box (`w`, `h`, `axis`, the height of its flow line) and `place` positions it: a `Compose`/`Chain` is a frame (header with name, p, runs bar, id) with its steps in a row joined by arrows, a `OneOf` its card, a fork to the stacked branches (weight boxes on the fork lines) and a join back to the axis, `Node`/`Modifier` a card with a row per input (click: the input's augmentation); cards show data paths shortened to their names (`shortPath`: `Lamp › energy`, full path on hover, wrapping to 2 lines) and `value_range` as `low – high`, anything collapsed or else a card; roots stacked with start/end dots. SVG lines (arrow marker) with width/opacity from `reached`, observed bars with an expected tick, neutral colors, a thin orange edge when |z| > 3 (z from the binomial standard error), collapsible nodes, a details panel; light and dark via `prefers-color-scheme`. Check it with headless Chrome (`--headless=new --screenshot`).
  - `bop` writes `<output>/<split>/<scene_id>/` (default `<path>/bop/train_pbr/000000`), image ids = datapoint indices, `obj_id` = class number from 1 (`obj_ids.json`), mm via the camera's `unit_scale`. It needs `poses` and `camera.intrinsics` in every label; when the dataset has masks, every visible pose needs an instance mask and a full mask (`mask_visib/`, `mask/`, `scene_gt_info.json` from them, `None` files as empty masks); `passes.Depth` becomes a 16-bit `depth/` PNG (background, ≥ `clip_end` and overflow → 0). `check_scales` raises when a class's scale varies, since BOP has one model per class. Without masks or depth it needs no numpy / OpenImageIO beyond the hard numpy dependency.

Intended loop (see `example.py`): for N datapoints, inside `with state.restoring():`, apply the augmentation `Compose`s and call the generating `Compose`.

## Version differences

- Blender 5 moved geometry nodes modifier inputs from id properties to `modifier.properties.inputs.Socket_2.value`, so data paths for them differ by version. On 4.x the path is `modifiers["GeoNodes"]["Socket_2"]`; on 5.x it is `modifiers["GeoNodes"].properties.inputs.Socket_2.value`.
- On 5.x, geometry nodes modifier menu inputs list their options via RNA; on 4.x they are int id properties.
- Blender 4.2 Workbench leaves 0.0005 RGBA in empty transparent pixels (0 from 4.5).
- Blender 5 needs `image_settings.media_type` set alongside `file_format` (`set_file_format` in `generating/bpy_images.py`).
- Blender 5.2 EEVEE bug: a VALUE AOV listed before a COLOR AOV in the view layer renders as 0 (Cycles is fine). Listing color AOVs first avoids it.
- Blender 5.2 warns that `Material.use_nodes` and light node trees are going away in Blender 6.
